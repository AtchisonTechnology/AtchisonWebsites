## Problem/Requirement

The Software Architecture Insights (SAI) podcast is coming back from its summer
break. Podcast planning lives outside this repo, in Lee's Dropbox folder
"Software Architecture Insights/Podcast" (`Launch Todo List.md` there holds the
dated decisions this spec implements). The site needs three things before the
first episode back can publish:

1. **A `/podcast` landing page**, linked from the main menu.
2. **One page per episode** at `/podcast/<episode-id>/`.
3. **A permanent "Listen to the episode" link** on any article an episode is
   built from.

Requirements decided by Lee (2026-09-11):

- `/podcast` contents: short show pitch; subscribe buttons (Apple Podcasts,
  Spotify, RSS); Captivate's **Latest Episode Player**; a list of every
  episode, newest first (title, date, category, one-line summary, link to the
  episode page), generated by the build — no hand-maintained list; the Kit
  newsletter sign-up. **No** Captivate Show Player.
- Episode page contents: Captivate **Single Episode Player**; summary and key
  points; link to the source article(s); transcript; guest bio (interviews);
  related episodes; Kit sign-up.
- Episode pages are their own collection, **kept out of the article feed**
  (`feed.xml`). Captivate's RSS is the only podcast feed.
- Episode IDs are lowercase hyphenated slugs with a category prefix, fixed once
  assigned, independent of the episode number: `beyond-` (Beyond the Article),
  `then-now-` (Then vs. Now), `teardown-` (Teardown), `asked-` (Questions I Get
  Asked), `course-` (Course Spin-off), `interview-` (Interview), `reading-`
  (Reading). Tags: Contrarian, Series.
- Episodes release **Tuesdays 3:30 am Pacific**. The episode page must be live
  before then, because each episode's website link in Captivate points to it.
  The weekly rebuild was moved to 10:00 UTC for this (see History).
- Episode pages must be producible **automatically** from material the podcast
  pipeline already has (script, transcript, publish packet). Nothing on the
  site may need hand upkeep per episode beyond adding the episode file.

## Solution/Fix/Change

All Open Questions resolved by Lee on 2026-09-11; this section reflects those decisions.

### 1. `episodes` collection

In `bridgetown.config.yml`:

```yaml
collections:
  episodes:
    output: true
    permalink: /podcast/:slug/
    sort_by: date
    sort_direction: descending
defaults:
  - scope: { collection: episodes }
    values: { layout: episode }
```

Files: `src/_episodes/YYYY-MM-DD-<episode-id>.md`, the same date-prefix filing
convention as articles. Proposed front matter:

```yaml
title: "Why Caches Lie"
slug: beyond-why-caches-lie        # the episode ID
date: 2026-10-06                    # release Tuesday
episode_number: 13                  # assigned at scheduling; may change before release
category: Beyond the Article        # one of the seven categories
tags: [Contrarian]                  # optional: Contrarian, Series
description: "One-line summary for the list and meta tags."
captivate_episode_id: "…"           # for the Single Episode Player embed
source_articles: [why-caches-lie]   # article slugs; empty for teardowns etc.
guest: { name: "…", bio: "…" }      # interviews only
duration: "15:42"
```

No per-episode image: every episode uses the show art (Lee, 2026-09-11).

Body: summary and key points, then the transcript. Generated by the podcast
pipeline from its publish packet and the Descript transcript.

### 2. Builder: validation and future-date filter

Extend `plugins/builders/sai_content.rb` (or add a sibling builder) to:

- Validate each episode: filename date prefix matches `date`; `slug` starts
  with one of the seven prefixes; `category` matches the prefix;
  `tags` only from the allowed set; every `source_articles` slug exists in the
  articles collection. Fail the build on a violation, same posture as articles.
- Fix the future-date filter's timezone: compare against today's date in
  **Pacific time** (`America/Los_Angeles`), not the build server's UTC date.
  Applies to articles and episodes alike.
- Apply the **future-date filter** to episodes, so an episode file can
  be committed ahead of its Tuesday and appears only after the scheduled
  rebuild — the same mechanism articles use.

### 3. Layouts and pages

- `src/podcast.erb` → `/podcast/`: show art (600 px), pitch, subscribe buttons
  (Apple Podcasts, Spotify, RSS), Latest Episode Player embed, generated
  episode list, `kit_form` partial. The list is unpaginated and capped at the
  **50 most recent** episodes, so it stays bounded as the show grows without
  anyone revisiting it (Lee, 2026-09-11). Older episodes remain reachable by
  their own URLs, the sitemap, and their source articles.
- `src/_layouts/episode.erb`: title, date, category, Single Episode Player,
  body (summary, key points), source article link(s), guest bio, full
  transcript inside a collapsed "Show transcript" `<details>` section (still
  in the HTML, so search engines read it), up to three
  related episodes (same category, then most recent), `kit_form`.
- Captivate players are iframes. The site's `X-Frame-Options: DENY` only stops
  others framing this site, and there is no Content-Security-Policy, so
  embedding works as-is.

### 4. Article → episode link

**Decided (Lee, 2026-09-11): reverse lookup.** The podcast decision says the
article gets an episode field in its front matter. But article-process requires
the repo copy of an article to stay byte-identical to its archived draft, so
editing a published article's file each time an episode ships would break that
rule.

Instead, a **reverse lookup**. The episode declares
`source_articles`; `article.erb` finds any published episode that lists the
current article's slug and renders a "Listen to the episode" block. No article
file is ever edited, and the link appears automatically the build after the
episode goes live.

### 5. Navigation, feed, sitemap

- Add `{ label: "Podcast", path: "/podcast" }` to `Shared::Navbar::LINKS`.
- `feed.xml.erb` already reads only `site.collections.articles`, so episodes stay
  out of the feed with no change.
- `sitemap.xml.erb` picks up any resource URL ending in `/`, so `/podcast/` and
  each episode page are included automatically. Confirm during testing.
- Social-share image (`og:image`) for `/podcast/` and every episode page: the
  show art.
- The existing UTM rewrite (sai-email → sai-web) applies to episode pages too,
  since it runs on every page's rendered HTML.

## Testing

- Build locally with two sample episodes (one past-dated, one future-dated) and
  one sample source article.
- Production-mode build: the future-dated episode is absent from `/podcast/`,
  its own URL, the sitemap, and the article's episode link; the past-dated one
  is present everywhere.
- Each validation rule fails the build with a clear message when broken.
- With 51+ sample episodes (can be generated in a test), `/podcast/` lists only
  the 50 most recent.
- A production build at 6:00 pm Pacific Monday (simulated clock) does not show
  Tuesday-dated content; one at 12:30 am Pacific Tuesday does.
- `/podcast/` and an episode page render the Captivate players (use a real
  Captivate episode ID from last season).
- `feed.xml` contains no episodes.
- Navbar shows Podcast, active state works.
- Phone width: players and episode list readable.
